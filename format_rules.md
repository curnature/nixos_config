# Format Rules

This file defines the indentation and formatting rules for everything under
`nixos_config/`. When reformatting any file in this directory, follow these
rules first.

## Golden Rules

1. **4-space indentation** is the default for all editable text configs.
2. **Spaces only** — no tabs.
3. **Never touch generated files:**
   - `hosts/omen/hardware-configuration.nix` — generated by
     `nixos-generate-config` and may be regenerated later.
   - `flake.lock` — generated by `nix flake update`.
4. **Never touch binary assets** (`wallpapers/`, `templates/*.png`, images).
5. **Leave `*.nix_bkup` files as-is** — they are backups, not live config.
6. **Do not run `nix fmt`**, `nixfmt`, `nixfmt-rfc-style`, `alejandra`, or
   `nixpkgs-fmt` on `.nix` files. They are opinionated formatters that force
   2-space indentation and will undo the 4-space style.
7. **Validate after reformatting:**
   - Each changed `.nix` file must pass `nix-instantiate --parse <file>`.
   - The whole flake must pass `nix flake check` (or at least `nix flake show`).

## File Type Rules

| File type | Indent-sensitive? | Rule |
| --- | --- | --- |
| `.nix` | No (except indented strings, see below) | 4 spaces. Structure comes from `{}`, `[]`, `let ... in`, and `;`. |
| `.yaml` / `.yml` | **Yes** | 4 spaces, no tabs. Indentation defines nesting; preserve hierarchy exactly. Use a YAML-aware formatter if available. |
| `.json` / `.jsonc` | No | 4 spaces. Whitespace is cosmetic. |
| `.ts` / `.tsx` / `.js` / `.jsx` | No | 4 spaces. For Prettier, set `tabWidth: 4`. |
| `.lua` | No | 4 spaces. Whitespace is cosmetic. |
| `.vim` / Vimscript | No | 4 spaces. Blocks use `if`/`endif`, not indentation. |
| `.kdl` | No | 4 spaces. Children are delimited by `{}`. |
| `.conf` (Hyprland / hypridle) | No | 4 spaces. Groups are delimited by `{}`. |
| `.conf` (INI-style, e.g. qt6ct) | No | No indentation needed; `[Sections]` and `key=value` lines stay at column 0. |
| `.toml` | No | 4 spaces. Whitespace is cosmetic. |
| `.sh` | No (except here-docs) | 4 spaces. Here-doc content is literal — do not re-indent it unless the here-doc supports `<<-` and tabs are used. |
| Markdown | No | 4 spaces for nested lists/code fences only if readability is unaffected. |

## Special Attention: Nix Indented Strings

Nix indented strings (`'' ... ''`) are the one place where leading whitespace
has semantic meaning. Nix strips the common leading indentation from the
non-empty lines of the string body.

When re-indenting a `.nix` file:

- Shift the opening `''`, the string body, and the closing `''` **by the same
  number of spaces**.
- Preserve the relative indentation between lines inside the string body.
- If in doubt, compare `nix-instantiate --eval` output before and after, or
  avoid touching the string body and only re-indent the surrounding Nix code.

## Known Exceptions

These files are intentionally allowed to differ from the 4-space rule:

- `hosts/omen/hardware-configuration.nix` — generated file; currently 2-space;
  leave it alone even if it does not match.
- `flake.lock` — generated file; leave it alone.
- `*.nix_bkup` — backups; leave them alone.

## Editor Settings (4-Space Enforcement)

- **Vim / Neovim:** `shiftwidth=4`, `tabstop=4`, `softtabstop=4`,
  `expandtab`. Add filetype overrides for `nix`, `yaml`, `json`, `lua`, `kdl`.
- **VS Code:** `editor.tabSize = 4`, `editor.insertSpaces = true`,
  `editor.detectIndentation = false`, and `[nix].editor.tabSize = 4`.
  Do **not** configure `nixpkgs-fmt`/`nixfmt` as the Nix formatter.
- **EditorConfig:** optionally add `.editorconfig` with `indent_style = space`
  and `indent_size = 4`.
